# AI 视频制作平台 PRD v1

## 背景

当前产品已有对话生成、专业画布、Task 查询、个人信息、历史记录、管理后台等基础能力。下一阶段目标是把这些能力从“可用工具集合”升级成“完整 AI 视频制作工作流”：用户能快速生成、稳定追踪、连续创作、管理素材、复用结果，并且失败时知道下一步该怎么做。

## 产品目标

- 降低用户找到任务、结果、失败原因的成本。
- 让生成流程更可预期，减少“点了生成但不知道发生了什么”。
- 让画布更像视频制作工具，而不是纯节点编辑器。
- 支持连续视频制作中的素材复用、首尾帧继承、镜头链管理。

## 目标用户

- 内容创作者：快速做短视频、广告片、Logo 动画、产品展示。
- 设计 / 运营团队：需要多版本生成、对比、复用素材。
- 高级用户：需要画布化管理镜头、任务、结果、失败日志。

## 核心信息架构

- 首页：进入制作、进入画布、进入个人信息。
- 对话制作：自然语言生成、参数确认、任务进度、结果续写。
- 专业画布：镜头节点、结果节点、素材节点、连续视频链。
- 任务中心：所有生成任务、状态、结果、失败原因、重拉取。
- 素材库：参考图、首帧、尾帧、生成视频、末帧资产。
- Task 查询：单个 Task 的完整结果和日志。

## 第一阶段：任务中心化

### 目标

把 `/profile` 的历史记录升级为“任务中心”，成为用户追踪所有生成结果的主入口。

### 功能需求

展示当前用户所有任务：

- 本地 Task ID
- 上游 Task ID
- 项目名
- 来源：对话 / 画布 / 测试任务
- 状态：等待中、生成中、已完成、失败、取消、过期
- 进度
- 创建时间、更新时间、完成时间
- 视频缩略预览
- 视频 URL / Result URL
- 失败原因

筛选能力：

- 状态
- 项目
- 来源
- 时间范围
- 是否有视频结果
- 是否失败

搜索能力：

- 本地 Task ID
- 上游 Task ID
- 视频 URL
- 项目名

操作能力：

- 复制 Task ID
- 复制上游 Task ID
- 复制视频 URL
- 打开完整 Task 查询页
- 重新拉取结果
- 打开关联画布节点
- 查看错误事件

批量操作：

- 批量重新拉取运行中 / 失败任务
- 批量复制已完成视频 URL
- 批量导出 CSV

### 交互要求

- 任务中心使用列表 + 右侧详情抽屉。
- 列表展示高密度信息，详情展示完整信息。
- 失败任务必须直接展示失败原因和推荐动作：
  - API key 问题：去修改 API key
  - provider 超时：重新拉取
  - 参数错误：回到源镜头修改
  - 本地节点丢失：恢复节点 / 打开 Task 查询

### 验收标准

- 用户可以在 10 秒内通过 Task ID 找到任意历史任务。
- 已完成任务可以直接播放视频。
- 失败任务可以看到错误原因和下一步操作。
- 运行中任务可以手动刷新状态。

## 第二阶段：生成流程标准化

### 目标

让用户在提交生成前明确知道“这次会生成什么、用什么参数、会产生什么任务”。

### 功能需求

对话生成前增加“参数确认卡”：

- Prompt
- Negative Prompt
- 模型
- 时长
- 比例
- 分辨率
- 首帧 / 尾帧 / 参考图
- 镜头运动
- 运动强度
- 是否生成音频
- 是否水印

画布生成前也使用同一套确认逻辑。

参数确认卡支持：

- 直接编辑关键参数
- 展开高级参数
- 保存为镜头模板
- 确认后生成

生成提交后立即创建本地任务卡：

- 显示 Task ID
- 显示状态
- 显示“正在提交 / 上游已接收 / 生成中 / 已完成 / 失败”

生成失败时区分：

- 提交失败：没有上游 Task ID
- 生成失败：上游返回失败
- 本地同步失败：已有上游 Task ID，但本地显示异常

### 交互要求

- “解析创意”和“提交生成”必须是两个明确动作。
- 用户可以在提交前修改参数。
- 提交后不能让用户误以为没有任务产生。
- 如果已有上游 Task ID，即使本地异常，也要继续允许拉取结果。

### 验收标准

- 每次生成前都有参数确认。
- 每次点击生成后都能看到本地 Task ID。
- 用户能区分“提交失败”和“生成失败”。
- 失败后有明确恢复入口。

## 第三阶段：画布升级为视频制作工具

### 目标

让专业画布从“节点存放区”升级为“镜头编排和连续视频制作工具”。

### 功能需求

画布节点优化：

- Shot 节点：输入参数、参考图、首尾帧、生成按钮
- Render 节点：视频预览、Task ID、状态、续写、重新拉取
- Asset 节点：图片 / 视频 / 末帧素材
- Note 节点：备注和脚本

画布底部时间线：

- 默认不遮挡画布
- 有内容时可展开 / 收起
- 展示已完成片段顺序
- 支持拖拽调整顺序
- 支持播放整条链
- 支持复制所有视频 URL

节点操作：

- 生成
- 续写下一段
- 复制源镜头
- 设为下一段首帧
- 加入主线
- 从主线移除
- 打开 Task 查询

主线版本：

- 用户可以把多个 render 节点加入一个“主线视频链”
- 主线顺序独立于画布位置
- 支持保存多个版本：v1、v2、客户版、备选版

### 交互要求

- 画布顶部只放全局工具：搜索、Task 查询、个人信息、日志。
- 画布右侧只放当前选中节点属性。
- 底部时间线可折叠，不能长期挡住节点。
- Render 节点必须能直接看到 Task ID 和视频状态。

### 验收标准

- 用户能在画布里完成一条 3-5 段连续视频链。
- 不需要打开日志也能知道每个节点的生成状态。
- 底部时间线不会挡住核心操作。
- 用户能从任意结果节点继续生成下一段。

## 第四阶段：素材和连续性

### 目标

解决连续视频制作中最关键的问题：风格、画面、首尾帧、素材复用。

### 功能需求

素材库：

- 参考图
- 上传图片
- 生成视频
- 视频末帧
- 首帧素材
- 尾帧素材

素材来源记录：

- 来自上传
- 来自生成结果
- 来自视频末帧提取
- 来自外部 URL

素材操作：

- 复制 URL
- 设为某个 Shot 的参考图
- 设为首帧
- 设为尾帧
- 预览
- 删除

连续性控制：

- 一键使用上一段末帧作为下一段首帧
- 继承上一段模型、比例、风格、运动强度
- 支持“锁定风格”
- 支持“锁定主体”
- 支持“仅改变镜头运动”

镜头链模板：

- 开场
- 产品展示
- Logo 收尾
- 人物口播
- 场景推进
- 三段式广告

### 交互要求

- Render 节点完成后自动提取末帧素材。
- 用户点击“续写下一段”时，默认带入上一段末帧。
- 用户可以清楚看到下一段继承了哪些参数。
- 素材库要和画布打通，不能只是文件列表。

### 验收标准

- 用户能用上一段末帧快速创建下一段。
- 用户能复用历史素材到新镜头。
- 连续视频的比例、模型、风格保持稳定。
- 素材来源可追踪。

## 优先级建议

### P0

- 任务中心
- 参数确认卡
- 画布底部时间线折叠
- Render 节点 Task ID / 状态 / 重新拉取
- API key 修改和历史任务

### P1

- 主线视频链
- 素材库
- 末帧自动提取和复用
- 批量任务操作
- 失败原因推荐动作

### P2

- 多版本管理
- 镜头链模板
- 风格锁定
- 主体一致性配置
- 导出成片方案

## 核心指标

- 生成成功后用户找到结果的平均时间
- 失败任务恢复率
- 单用户平均连续片段数
- Task 查询使用次数
- 历史任务复用率
- 从首段生成到完成 3 段视频链的平均时间

## 下一步建议

先做 P0：任务中心、参数确认卡、画布时间线、Render 节点状态恢复。

这四个做好后，产品会从“能生成”变成“能持续制作和管理”。
