Seedance 视频生成接口原理

这个本地站点把浏览器请求先送到 Node 后端，再由后端携带 API key 调用 New API。视频生成不是同步返回视频文件，而是先创建任务，再轮询任务状态。

请求链路

浏览器 填写提示词、图片、时长、画幅
→
本地后端 POST /api/videos
→
New API POST /v1/video/generations
→
异步任务 返回 task_id，随后查询状态

本地后端做了什么

前端不会直接访问模型供应商，也不会拿到 API key。浏览器只请求本地 Express 服务，后端再把请求转发到配置的 base URL。 

POST http://localhost:1234/api/videos
GET  http://localhost:1234/api/videos/{taskId}
POST http://localhost:1234/api/config

上游接口怎么请求

当前项目适配的是 New API 网关的视频生成接口。鉴权放在后端请求头里： 

POST {NEWAPI_BASE_URL}/v1/video/generations
Authorization: Bearer $NEWAPI_API_KEY
Content-Type: application/json

文生视频参数

文生视频的最小输入是模型和提示词，其他参数用于控制输出规格。

{
  "model": "seedance-2.0-720p",
  "prompt": "清晨池塘上的纸船，电影感镜头推进",
  "duration": 5,
  "width": 1280,
  "height": 720,
  "metadata": {
    "ratio": "16:9",
    "resolution": "720p",
    "watermark": false
  }
}

图生视频参数

图生视频比文生视频多一个图片输入。这个项目支持图片 URL，也支持把本地图片转成 data URL 后交给后端。 

{
  "model": "seedance-2.0-720p",
  "prompt": "让画面产生轻微运镜，人物自然眨眼",
  "image": "https://example.com/image.jpg",
  "duration": 5,
  "metadata": {
    "ratio": "16:9",
    "resolution": "720p"
  }
}

核心参数

参数 作用 当前默认值
model 选择视频模型或网关里的模型 ID。 seedance-2.0-720p
prompt 描述视频内容、镜头运动、风格和限制。 用户输入
image 图生视频的参考首帧或参考图。 图生视频必填
duration 视频时长，单位秒；成本和等待时间会随之增加。 5
ratio / width / height 控制横屏、竖屏或方图输出。 16:9 / 1280×720
resolution 控制清晰度规格。 720p
seed 可选；固定后更便于复现相近结果。 空

同步还是异步

是异步。创建接口只负责排队并返回任务 ID，不会立刻返回 mp4。前端拿到 taskId 后，每 3 秒请求一次本地查询接口，直到状态变成 completed。 

1. POST /api/videos
2. 得到 taskId
3. 循环 GET /api/videos/{taskId}
4. completed 后读取 url 并播放视频

状态怎么理解

queued 表示排队，in_progress 表示生成中，completed 表示可播放。 failed、cancelled、expired 都是终止状态。 

{
  "taskId": "cgt-...",
  "status": "completed",
  "url": "https://.../result.mp4"
}

为什么要后端代理

API key 属于敏感凭证。放在浏览器里会被任何人看到，所以必须由本地后端读取 NEWAPI_API_KEY，再把安全的任务结果返回给前端。

当前权限提示

如果请求返回“无权访问 auto 分组”，说明 token 所属分组没有权限访问当前模型或 当前网关分组。这不是前端问题，也不是同步异步问题。

失败时看什么

失败后点击“查看错误详情”，可以看到上游请求体、响应状态和完整返回体。 API key 会保留在后端，不会明文展示。
